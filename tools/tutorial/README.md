# The standalone tutorial

`TUTORIAL.html` is a single self-contained page published at the site root:
<https://djgriffin13.github.io/rnetis/TUTORIAL.html>. It is not a vignette. It
is generated by the scripts in this directory and committed as a build product
under `pkgdown/assets/`, which pkgdown copies to the site root unchanged.

## Why it is generated rather than written

Every code block on the page, and every result underneath it, comes out of
`out/`: the `.R` file that was evaluated supplies the code, and its sibling
`.txt` supplies what R printed. The builder refuses to emit a block whose
capture is missing, so the page cannot show code that was never run, or output
that was not produced by the code above it. Warnings and refusals are captured
the same way, which is why the refusal messages on the page are reproduced in
full rather than paraphrased.

The capture scripts fail loudly in two directions. A block marked
`expect_error = TRUE` that *succeeds* writes a `.problem` file, because a page
that teaches a refusal and shows no refusal is worse than no page. So does a
block that fails when it was not meant to.

## Rebuilding

Run them in this order. **`run-e.R` has to be last**, for the reason in the
last section.

```
Rscript cap.R            # sourced by the run scripts; not run directly
Rscript run-inf.R out    # the Influence sequence, A1 to A8, and its figures (~3 min)
Rscript run-a.R out      # Getting started and the reference pages' data blocks (~10 s)
Rscript run-c.R out      # reference pages                       (~1 s)
Rscript run-g.R out      # the hand-built team data, fit statistics, interop (~30 s)
Rscript run-b.R out      # the Selection path                    (~5 min)
Rscript run-d.R out      # the hierarchical block, as one unit   (~8 min)
Rscript run-f.R out      # the convergence block, from that chain  (~1 s)
Rscript run-e.R out      # every figure, at publication width    (~3 min)
python  make.py          # assemble and copy into pkgdown/assets/
```

`make.py --dry` builds into this directory instead, for checking. It needs
`logo.png` beside it — `cp ../../man/figures/logo.png .` — which the
published page gets from the site root instead.

Check for `out/*.problem` after any run; there should be none. `make.py` exits
non-zero and names anything it could not find, and lists any capture on disk
that no page displays.

`run-d.R` refits the hierarchical model and saves it to `out/hier.rds` so that
`run-e.R` can draw its panel from the same chain the tables came from, rather
than from a second chain that would disagree with them. That file is not
committed; without it `run-e.R` skips the hierarchical panel and says so.
`run-f.R` reads the same file, so it has to run after `run-d.R`.

## How a page is put together

- `build.py` — the block constructors and the page template. `code()`,
  `result()` and `block()` read `out/`; `fig()` places a captured ggplot;
  `dia()` places a hand-drawn SVG; `eq()` places a display equation.
- `content.py` — the pages, in order. It imports `content_start.py` (Welcome
  and Getting started) and `content_influence.py` (the Influence sequence, A1
  to A8) at the point where their pages belong, and holds the Selection pages,
  Feedback, Reference and Help itself. Importing registers the pages.
- `diagrams.py` — the SVG diagrams. These are *conceptual* figures and carry
  no number from a fit; anything reporting an estimate is a captured ggplot,
  so no drawing on the page can disagree with a result.
- `cap.R` — `cap()` writes a block and its output, `capfig()` a figure,
  `setup()` runs code for its side effects without writing anything (for
  objects later captures need, and for blocks a page has stopped showing), and
  `fact()` records a single value for the prose to quote.

Running everything needs the suggested packages the page uses: `amen`,
`latentnet`, `clubSandwich` and `igraph`.

## What is committed

- `out/*.R` and `out/*.txt` — the captures, so the page can be rebuilt without
  re-running the Markov chains.
- the scripts and the builder.

`pkgdown/assets/TUTORIAL.html` and `pkgdown/assets/tutorial-figures/` are the
build products. They are committed too, because the deploy workflow builds the
site from the repository and does not run anything in this directory.

`out/png/` is **not** committed: it is where the R scripts render, and
`pkgdown/assets/tutorial-figures/` holds the same images. `build.py` looks in
`out/png/` first and falls back to the published copies, so a clean checkout
rebuilds the page without re-rendering, while a fresh render still wins.

## Two things that will bite

`tools/clean-site.R` carries an allowlist of files expected at the site root,
and the deploy workflow **fails the publish** on anything not in it. Both
`TUTORIAL.html` and `tutorial-figures` are listed there. Renaming either means
editing that list in the same commit.

The figures are saved wide (`W` in `run-e.R`) on purpose. rnetis's plot theme
carries a wide categorical legend and a multi-line caption, and `ggsave()`
clips them rather than shrinking them — a narrower figure loses the right-hand
end of the legend without any error.

Which is why **`run-e.R` has to be the last script you run**. `run-a.R` and
`run-b.R` render the same figures at their own, narrower widths as a
by-product; re-running either on its own silently replaces the publication
renders in `out/png/` with clipped ones, and nothing errors. If you re-run
anything, finish with `run-e.R`.

## The Influence sequence, and what is still to come

The Influence sequence (A1 to A8) is in its rewritten form: each page runs code
first, explains it a piece at a time, and keeps the detail in expandable boxes.
It uses `demo_affect` and `demo_affect_teams`, which ship with the package;
page A3 rebuilds `demo_affect` from scratch, and `run-inf.R` stops if what the
page builds is not identical to the shipped object. That check is what keeps
the page's code and `data-raw/demo-affect.R` the same code.

`run-inf.R` needs the **installed** rnetis to be the version in this checkout
(`devtools::install(".")`), because the captures call `library(rnetis)`.

Not yet done:

- **Selection** keeps its earlier pages, on the earlier example data, with
  output captured before `print()` and `summary()` changed. It is to be
  rewritten to the Influence plan, page for page, on the same team data.
- **The advanced walkthroughs** (one per family, each ending in a table of the
  functions worth knowing) are not written. The material the earlier Influence
  pages held on moderation, missing data, simulation, sensitivity and
  binary-versus-weighted ties is in git history, and belongs there.
- `run-a.R`, `run-g.R` and `run-h.R` to `run-l.R` still produce captures that
  only the earlier Influence pages showed. `make.py` lists them as unused.
  They stay until the advanced walkthrough decides which of them it reuses.
- `OUTLINE.md` describes the earlier plan.
