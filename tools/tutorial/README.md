# The standalone tutorial

`TUTORIAL.html` is a single self-contained page published at the site root:
<https://djgriffin13.github.io/rnetis/TUTORIAL.html>. It is not a vignette. It
is generated by the scripts in this directory and committed as a build product
under `pkgdown/assets/`, which pkgdown copies to the site root unchanged.

## Why it is generated rather than written

Every code block on the page, and every result underneath it, comes out of
`out/`: the `.R` file that was evaluated supplies the code, and its sibling
`.txt` supplies what R printed. The builder refuses to emit a block whose
capture is missing, so the page cannot show code that was never run, or output
that was not produced by the code above it. Warnings and refusals are captured
the same way, which is why the refusal messages on the page are reproduced in
full rather than paraphrased.

The capture scripts fail loudly in two directions. A block marked
`expect_error = TRUE` that *succeeds* writes a `.problem` file, because a page
that teaches a refusal and shows no refusal is worse than no page. So does a
block that fails when it was not meant to.

## Rebuilding

```
Rscript cap.R            # sourced by the run scripts; not run directly
Rscript run-a.R out      # data pages and the Influence path     (~10 s)
Rscript run-c.R out      # reference pages                       (~1 s)
Rscript run-b.R out      # the Selection path                    (~10 min)
Rscript run-d.R out      # the hierarchical block, as one unit   (~8 min)
Rscript run-e.R out      # every figure, at publication width    (~3 min)
python  make.py          # assemble and copy into pkgdown/assets/
```

`make.py --dry` builds into this directory instead, for checking.

Check for `out/*.problem` after any run; there should be none. `make.py` exits
non-zero and names anything it could not find.

`run-d.R` refits the hierarchical model and saves it to `out/hier.rds` so that
`run-e.R` can draw its panel from the same chain the tables came from, rather
than from a second chain that would disagree with them. That file is not
committed; without it `run-e.R` skips the hierarchical panel and says so.

Running everything needs the suggested packages the page uses: `amen`,
`latentnet`, `clubSandwich` and `igraph`.

## What is committed

- `out/*.R` and `out/*.txt` — the captures, so the page can be rebuilt without
  re-running the Markov chains.
- the scripts and the builder.

`pkgdown/assets/TUTORIAL.html` and `pkgdown/assets/tutorial-figures/` are the
build products. They are committed too, because the deploy workflow builds the
site from the repository and does not run anything in this directory.

`out/png/` is **not** committed: it is where the R scripts render, and
`pkgdown/assets/tutorial-figures/` holds the same images. `build.py` looks in
`out/png/` first and falls back to the published copies, so a clean checkout
rebuilds the page without re-rendering, while a fresh render still wins.

## Two things that will bite

`tools/clean-site.R` carries an allowlist of files expected at the site root,
and the deploy workflow **fails the publish** on anything not in it. Both
`TUTORIAL.html` and `tutorial-figures` are listed there. Renaming either means
editing that list in the same commit.

The figures are saved wide (`W` in `run-e.R`) on purpose. rnetis's plot theme
carries a wide categorical legend and a multi-line caption, and `ggsave()`
clips them rather than shrinking them — a narrower figure loses the right-hand
end of the legend without any error.
