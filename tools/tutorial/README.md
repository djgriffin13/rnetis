# The standalone tutorial

`TUTORIAL.html` is a single self-contained page published at the site root:
<https://djgriffin13.github.io/rnetis/TUTORIAL.html>. It is not a vignette. It
is generated by the scripts in this directory and committed as a build product
under `pkgdown/assets/`, which the `tutorial` workflow publishes.

## How the tutorial is laid out

- **Getting started**: Welcome, Overview, Installation.
- **Influence**, pages A1 to A8, and **Selection**, pages B1 to B8. The two
  sequences follow one plan, page for page: run a model, the theory, the data,
  running the model, interpreting it, visualizing it, the latent version, and
  several teams. Each page runs code first, explains it a piece at a time, and
  keeps options and detail in expandable boxes.
- **Advanced**: one walkthrough per family. Each goes back over its sequence
  and shows the alternatives at every step, and ends with a table of functions.
- **Feedback**, **Reference** and **Help**.

Both families use the same data, `demo_affect` and `demo_affect_teams`, which
ship with the package. Page A3 rebuilds `demo_affect` from scratch, and
`run-inf.R` stops if what the page builds is not identical to the shipped
object. That check is what keeps the page's code and `data-raw/demo-affect.R`
the same code.

## Why it is generated rather than written

Every code block on the page, and every result underneath it, comes out of
`out/`: the `.R` file that was evaluated supplies the code, and its sibling
`.txt` supplies what R printed. The builder refuses to emit a block whose
capture is missing, so the page cannot show code that was never run, or output
that was not produced by the code above it. Warnings and refusals are captured
the same way, which is why the refusal messages on the page are reproduced in
full rather than paraphrased.

The capture scripts fail loudly in two directions. A block marked
`expect_error = TRUE` that *succeeds* writes a `.problem` file, because a page
that teaches a refusal and shows no refusal is worse than no page. So does a
block that fails when it was not meant to.

Numbers quoted in the prose of the two sequences come from the capture too:
`fact()` in a run script records a value, and `F()` in a content file reads it.

## Rebuilding

The captures call `library(rnetis)`, so the **installed** rnetis has to be the
version in this checkout: run `devtools::install(".")` first.

```
Rscript run-start.R out        # the Installation page                    (~1 s)
Rscript run-inf.R out          # Influence, A1 to A8, and its figures     (~7 min)
Rscript run-sel.R out          # Selection, B1 to B8, and its figures     (~30 min)
Rscript run-adv-inf.R out      # the advanced Influence walkthrough       (~10 min)
Rscript run-adv-sel.R out      # the advanced Selection walkthrough       (~10 min)
Rscript run-latent-figs.R out  # only when a latent-coordinates panel changed (~4 min)
python  make.py                # assemble and copy into pkgdown/assets/
```

Each script stands alone and they can be run in any order. `cap.R` is sourced
by all of them and is not run directly.

`make.py --dry` builds into this directory instead, for checking. It needs
`logo.png` beside it (`cp ../../man/figures/logo.png .`), which the published
page gets from the site root instead.

Check for `out/*.problem` after any run; there should be none. `make.py` exits
non-zero and names anything it could not find, and lists any capture on disk
that no page displays.

## How a page is put together

- `build.py`: the block constructors and the page template. `code()`,
  `result()` and `block()` read `out/`; `fig()` places a captured ggplot;
  `eq()` places a display equation; `rare()` makes an expandable box. The
  sidebar lists each page's sections, which are its `h3()` headings outside
  any expandable box.
- `content.py`: the pages, in order. It imports `content_start.py`,
  `content_influence.py`, `content_selection.py` and `content_advanced.py` at
  the point where their pages belong, and holds Feedback, Reference and Help
  itself. Importing registers the pages.
- `cap.R`: `cap()` writes a block and its output, `capfig()` a figure,
  `setup()` runs code for its side effects without writing anything, and
  `fact()` records a single value for the prose to quote.

Running everything needs the suggested packages the page uses: `amen`,
`latentnet`, `clubSandwich`, `sna` and `igraph`.

## What is committed

- `out/*.R` and `out/*.txt`: the captures, so the page can be rebuilt without
  re-running the Markov chains.
- the scripts and the builder.

`pkgdown/assets/TUTORIAL.html` and `pkgdown/assets/tutorial-figures/` are the
build products. They are committed too, because the deploy workflow publishes
from the repository and does not run anything in this directory.

`out/png/` is **not** committed: it is where the R scripts render, and
`pkgdown/assets/tutorial-figures/` holds the same images. `build.py` looks in
`out/png/` first and falls back to the published copies, so a clean checkout
rebuilds the page without re-rendering, while a fresh render still wins.

## Two things that will bite

`tools/clean-site.R` carries an allowlist of files expected at the site root
for the pkgdown build. Both `TUTORIAL.html` and `tutorial-figures` are listed
there. Renaming either means editing that list in the same commit.

The figures are saved wide (`W` in the run scripts) on purpose. rnetis's plot
theme carries a multi-line caption, and `ggsave()` clips it rather than
shrinking it: a narrower figure loses the right-hand end of a caption line
without any error. Look at a figure after changing its size.
